The package runs the [`@thorvg/webcanvas`](https://www.npmjs.com/package/@thorvg/webcanvas) API on Android, iOS and web. Code written against it draws the same result on every platform.

![react-native-thorvg architecture](/img/architecture.svg)

## Layers

| Layer | Role |
| --- | --- |
| Framework | The React Native entry points: `useThorVG`, the `Canvas` view, the [components](../components/overview) and the [views](../views/lottie-view) |
| Interface | The WebCanvas API. `Shape`, `Scene`, `Picture`, `Text`, `LottieAnimation` and the other classes have the same methods on every platform |
| Bindings | On Android and iOS, the classes call the ThorVG C API through JSI. On web, they are WebCanvas itself, running ThorVG as WebAssembly |
| Engine | ThorVG, which builds the scene and renders it |
| Render backends | The engine renders with the CPU (`'sw'`), OpenGL ES or WebGL (`'gl'`), or WebGPU (`'wg'`, Metal on iOS) |
| Surfaces | The result is shown in a `TextureView` or `SurfaceView` on Android, a `CAMetalLayer` on iOS and a `<canvas>` element on web |

## Native

On Android and iOS, ThorVG is compiled into the app and called directly, without a web view or WebAssembly. Each `Canvas` view owns a native surface, and `new TVG.Canvas(view)` creates a ThorVG canvas on it. Paints are ThorVG objects held by JavaScript and released when they are garbage collected or disposed.

## Web

On web, the package uses `@thorvg/webcanvas` directly. `new TVG.Canvas(view)` creates a WebCanvas `Canvas` on the `<canvas>` element of the view.

## Renderers

| Platform | Renderers | Default |
| --- | --- | --- |
| Android | `'gl'`, `'sw'` | `'gl'` |
| iOS | `'wg'`, `'sw'` | `'wg'` |
| Web | `'gl'`, `'wg'`, `'sw'` | `'gl'` |

Choose one with `init({ renderer })` or `useThorVG({ renderer })`. See [Platforms](../platforms) for details.
